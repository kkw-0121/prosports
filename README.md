# 프로스포츠 관중 수 대시보드

5개 프로스포츠(야구 KBO · 축구 K리그 · 남자농구 KBL · 여자농구 WKBL · 남녀배구 KOVO)의 관중 수를
매일 자동으로 모아 보여주는 사이트입니다. 버튼 한 번으로 기존 엑셀 양식과 똑같은 파일을 내려받을 수 있습니다.

## ① 사이트 주소

**https://kkw-0121.github.io/prosports/**

- 매일 **오전 0시 30분**(전날 밤 경기 반영)과 **오전 9시**(연맹의 늦은 정정 반영)에 자동으로 갱신됩니다.
  GitHub 사정에 따라 10~20분 늦게 시작할 수 있습니다.
- 오른쪽 위 **[엑셀 다운로드]** → `프로스포츠 관중 수(YY.MM.DD 기준).xlsx`
  - 원본 양식과 서식·수식·안내 상자가 같고, 숫자와 기준일만 최신으로 바뀝니다.
  - 맨 뒤에 **'공식 집계 대조'** 시트가 붙습니다 (경기별 합계와 연맹 공식 누적치 비교).
- 내 PC에서만 보고 싶을 때: 폴더의 `대시보드_열기.bat` 더블클릭 → 브라우저에서 http://localhost:8765

3. 약 5분 뒤 초록 체크(✓)가 되면 사이트가 새 숫자로 바뀝니다 (안 바뀌어 보이면 브라우저 새로고침)

> 노란 시계/원 = 대기·진행 중, 초록 ✓ = 성공, 빨간 ✕ = 실패

## ③ 수집이 실패했을 때

**실패하면 이렇게 알 수 있습니다**
- GitHub 가입 이메일로 "Run failed: 관중 수 수집" 메일이 옵니다.
- 사이트 위쪽 리그 배지가 **실패**(빨강) 또는 **지연**(노랑, 26시간 넘게 성공 못 함)으로 바뀝니다. 배지에 마우스를 올리면 사유가 보입니다.
- **실패해도 틀린 숫자는 저장되지 않습니다.** 그 리그는 마지막으로 성공한 숫자가 그대로 유지되고, 다른 리그는 정상 갱신됩니다.

**원인 확인 순서**
1. https://github.com/kkw-0121/prosports/actions 에서 빨간 ✕ 실행을 누릅니다.
2. **collect** → **수집 (리그별 독립 실행)** 단계를 펼치면 `[KBL] 실패: …` 처럼 리그와 사유가 나옵니다.
3. 같은 내용이 저장소의 `data/status.json` 에도 기록됩니다.
4. 실행 화면 아래 **Artifacts** 의 `raw-…` 파일에 그때 받은 원본 응답이 7일 동안 보관됩니다 (사이트 구조가 바뀐 경우 원인 파악용).

**자주 있는 원인과 대처**
| 메시지 예시 | 뜻 | 할 일 |
|---|---|---|
| 요청 실패 / timeout | 연맹 사이트가 잠깐 느리거나 점검 중 | 대개 다음 자동 실행에서 저절로 해결. 급하면 ② 수동 실행 |
| 이전에 있던 경기 N건이 빠짐 → 저장 안 함 | 연맹 사이트가 일부 경기를 빼고 보여줌 (안전장치 작동) | 하루 지켜보고 계속되면 연맹 사이트를 직접 확인 |
| 표를 찾지 못함 / 형식이 예상과 다름 / 응답이 JSON이 아님 | **연맹 사이트 화면이 개편됨** | 이 폴더에서 Claude Code를 열고 "수집 실패 메시지: (붙여넣기) 고쳐줘" 라고 요청 |
| 관중 0명 / 수용 인원 1.2배 초과 (경고) | 저장은 됐지만 값이 의심스러움 | 해당 경기를 연맹 사이트에서 확인 |

## ④ 새 시즌 추가 · 시즌 종료 처리

집계 규칙은 모두 `config/leagues.yaml` 한 파일에 있습니다. 각 리그의 `collect:` 목록이 **자동 수집하는 시즌**입니다.

```yaml
  KBL:
    collect: ["2026-2027"]      # ← 지금 자동 수집 중인 시즌
```

### 시즌이 시작될 때 → `collect` 에 추가
- **개막 전에** 추가해 두세요. 특히 **WKBL**은 경기별 관중이 공개되지 않아 "매일 합계가 늘어난 만큼"으로 경기별 관중을 계산하므로, 첫 경기 전에 수집을 시작해야 정규/PO를 나눌 수 있습니다.
- 현재 설정: KBO·K리그는 `2027` 이 이미 들어 있어 내년 개막부터 자동 수집됩니다.

### 시즌이 끝났을 때 → `collect` 에서 빼기
- 빼면 그 시즌은 **마지막 수집값으로 고정(확정)** 되고 더 이상 수집하지 않습니다. 화면에는 '확정'으로 표시됩니다.
- 예: K리그 2026 PO가 모두 끝나면 `collect: ["2026", "2027"]` → `collect: ["2027"]`

### 새 연도 행이 필요할 때 (예: 2027-28 시즌 → 엑셀 '2028' 행)
지금 엑셀 양식과 설정은 **2027 (2026-2027) 행까지** 있습니다. **KBL·WKBL·KOVO 2027-28 시즌이 개막하기 전(2027년 9월까지)** 아래 작업이 필요합니다.
1. 원본 엑셀 `프로스포츠 관중 수 양식.xlsx` 에 2028 행을 추가합니다 (종합 시트와 5개 리그 시트, 배구는 표 3개 모두).
2. 이 폴더에서 Claude Code를 열고 **"README의 새 연도 행 추가 절차대로 2028 행을 반영해줘"** 라고 요청하면 아래를 처리합니다.
   - `config/leagues.yaml` 의 `seasons` 에 2028 추가, 행 번호(`first_row`) 조정, `collect` 에 새 시즌 추가
   - `python scripts/build_baseline.py` → `python scripts/verify_baseline.py` (엑셀과 100% 일치 확인)
   - `python scripts/make_public_template.py` (다운로드용 양식 다시 만들기, 담당자 연락처 자동 제거)
   - `python scripts/build_summary.py`, 저장소에 올리기

## ⑤ 집계 규칙 바꾸기 (`config/leagues.yaml`)

| 바꾸고 싶은 것 | 고칠 곳 |
|---|---|
| 종목 합계에 넣을 항목 (예: 야구 = 정규 + PS + 올스타) | 리그의 `total:` 목록 |
| 화면에 보이는 종목 이름·약칭 | `name:`, `abbr:` |
| 세부 항목 이름·표시 순서 | `items:` 의 `label:` 과 줄 순서 (엑셀 칸 위치는 `first_row`·열 값이 따로 정함) |
| 자동 수집 시즌 | `collect:` |
| 이상값 경고 기준 (경기장 최대 수용 인원) | `max_capacity:` |
| 무관중 시즌 (0명 경고 안 함) | `no_crowd_seasons:` |

**GitHub 웹에서 바로 고치는 방법**
1. https://github.com/kkw-0121/prosports/blob/main/config/leagues.yaml 접속
2. 오른쪽 위 연필(✏️) 아이콘 → 수정 → 초록색 **Commit changes…** → **Commit changes**
3. 다음 자동 수집 때(또는 ② 수동 실행) 사이트에 반영됩니다.

> `first_row`, `attendance_col`, `games_col`, `summary_cols` 는 엑셀 칸 위치라서, 엑셀 양식을 바꾸지 않았다면 건드리지 마세요.
> 규칙을 바꾼 뒤에는 내 PC에서 `python scripts/verify_baseline.py` 로 엑셀 '종합' 시트와 숫자가 맞는지 확인할 수 있습니다.

### 이미 정해진 집계 범위
- **KBO 포스트시즌** = 와일드카드 + 준PO + PO + 한국시리즈
- **K리그 PO** = K리그2 준PO + PO + 승강 PO
- **KOVO 올스타전** = 남녀 공통 1경기 (남자부·여자부 경기가 한 행사로 열린 경우 1경기로 셈)
- **제외**: 시범경기, 컵대회(KOVO컵·KBL컵 등), 코리아컵, K리그 리그컵, KBL D리그, KOVO 기타매치, 엑셀에 항목이 없는 대회

## 알아두면 좋은 점

| 리그 | 내용 |
|---|---|
| KBO | 연맹 공식 누적치는 정규시즌만 제공 (PS·올스타는 '공식 누적치 미제공') |
| K리그 | 공식 누적치는 K리그1 누적 관중만 제공 |
| KBL | 공식 누적치는 시즌 전체(정규+PO) 합계만. 관중 목록에 원정팀 정보 없음 |
| WKBL | **경기별 관중을 공개하지 않음.** 시즌 합계만 정확하고, 경기별 관중은 대부분 비어 있음. 연맹 합계 반영이 늦어 경기 수가 실제 일정보다 1경기쯤 늦을 수 있음('반영 대기'로 표시) |
| KOVO | 공식 누적치는 시즌이 끝난 뒤에만 공개. 2022-23 공식 표의 '계' 칸 오류(600명) 때문에 공식 전체값은 항목 합으로 계산 |

- 지난 시즌(2020~2026 확정분)은 원본 엑셀의 숫자(`data/baseline.json`)를 그대로 씁니다.
- 원본 엑셀과 `PROMPT.md`, 디자인 참고 이미지는 저장소에 올리지 않습니다 (`.gitignore`).
- 다운로드용 양식(`site/template/양식.xlsx`)에는 담당자 연락처가 지워져 있습니다.

## 나중에 비공개로 바꾸려면
1. 저장소 **Settings → General → Danger Zone → Change visibility → Private**
2. GitHub 무료 계정은 비공개 저장소로 사이트를 운영할 수 없으므로, **Cloudflare Pages**(무료)에 이 저장소를 연결합니다. 빌드 명령 없음, 출력 폴더 `site`.
3. **Cloudflare Access** 로 허용할 이메일을 등록합니다 (50명까지 무료).
4. `.github/workflows/deploy.yml` 은 지워도 됩니다. 사이트 코드는 고칠 필요가 없습니다.

## 폴더 구성 (참고)

| 폴더/파일 | 내용 |
|---|---|
| `config/leagues.yaml` | 집계 규칙 (이 파일만 고치면 됨) |
| `data/baseline.json` | 엑셀에서 가져온 지난 시즌 확정값 |
| `data/games/` | 자동 수집한 경기별 관중 (리그·시즌별) |
| `data/official/` | 연맹 공식 누적치 |
| `data/status.json` | 리그별 마지막 성공 시각·실패 사유 |
| `scrapers/` | 리그별 수집 프로그램 |
| `scripts/` | 엑셀 변환·검증, 화면 데이터 만들기, 다운로드 양식 만들기 |
| `site/` | 사이트 화면 (HTML·CSS·JS), 다운로드 양식 |
| `docs/` | 단계별 작업 보고서와 대조표 |
| `.github/workflows/` | 매일 자동 수집(`collect.yml`)·사이트 배포(`deploy.yml`) |

내 PC에서 직접 실행하려면 Python 3.12 이상에서 한 번만:
```
pip install -r requirements.txt
python -m playwright install chromium
```
그다음 `python -m scrapers.run_all` (수집) → `대시보드_열기.bat` (보기)
