## 4. 수집하며 발견해 반영한 것
- **K리그 포털**: 연도를 바꾸면 조회 기간이 'YYYY/12/31~YYYY/12/31' 하루로 잡히는 문제 → 기간을 1/1~12/31로 직접 지정. 조건이 적용되지 않으면 실패 처리
- **KOVO 올스타전**: 남자부·여자부 올스타가 한 행사(같은 날·같은 체육관·같은 관중)로 두 줄 나옴 → 엑셀처럼 1경기로 합침 (관중 수가 다르면 실패 처리)
- **WKBL**: 진행 중 시즌은 구단별 관중이 없고 시즌 합계만 공개되고, 경기 후 합계 반영이 늦음
  - 새로 끝난 경기는 '반영 대기'로 두고 합계가 늘면 그 경기에 배정 (대기 경기가 1경기일 때만, 여러 경기면 경기별 관중은 비워 둠)
  - 반영 대기 경기는 경기 수에서 제외해 평균이 틀어지지 않게 함
  - 첫 수집 기준점은 엑셀 확정값(20경기·27,985명) 사용 (`config/leagues.yaml`의 `wkbl_anchor`)
  - 따라서 **WKBL은 경기별 관중이 대부분 비어 있고**, 정규/PO 합계는 `stage_totals`로 관리. PO가 시작되면 정규리그 종료 시점 합계를 고정하고 증가분을 PO로 계산
- **KBL**: 관중 목록에 원정팀이 없음 (홈팀·경기장·날짜·라운드만)
- **KOVO 공식 누적치**: 관중현황 표의 2022-23 '계' 칸(567,891)이 항목 합(567,291)보다 600명 많음 (다른 시즌은 모두 일치).
  → 공식 전체값은 '계' 칸 대신 정규리그+올스타전+포스트시즌 합으로 계산하고, 표의 값이 다르면 `site_total`과 메모로 남김.
  2022-23 시험 수집: 경기별 합 567,291 = 공식(항목 합) 567,291 = 엑셀

## 5. 안전장치 (확인 완료)
- 이전 수집에 있던 경기가 빠지면 저장하지 않고 실패 → 가짜 경기를 넣어 시험, 파일 유지·실패 기록 확인
- 리그별 독립 실행, 하나라도 실패하면 종료 코드 1 (GitHub Actions가 실패로 끝나 이메일 알림)
- `data/status.json`에 리그별 마지막 성공 시각·실패 사유 기록
- 검증: 관중 음수·숫자 아님 → 실패 / 0명(무관중 시즌 제외)·최대 경기장 수용 인원 1.2배 초과 → 경고
- **원본 응답 보관 방식 변경**: 1회 수집에 약 0.35MB(gzip). 하루 2회 저장소에 커밋하면 기록이 계속 커져서 `raw/`는 저장소에 올리지 않고 **GitHub Actions 첨부파일(artifact)로 7일 보관**하도록 Phase 4에서 설정 예정
